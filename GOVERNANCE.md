# Governance

Yukh Projects uses maintainer-led, transparent governance with public reasoning and secure handling of sensitive reports.

## Roles

### Contributors

Anyone who participates constructively through issues, documentation, code, review, or community support.

### Maintainers

Maintainers review contributions, protect project invariants, manage releases, respond to security reports, and make final decisions when consensus is not reached. The initial maintainer is `@nomed`.

New maintainers are selected based on sustained technical judgment, security awareness, neutrality discipline, constructive review, and reliable stewardship.

## Decision process

Routine changes are decided in pull requests. Material decisions involving architecture, compatibility, security boundaries, governance, data handling, or project invariants require an architectural decision record under `docs/adr/`.

Maintainers seek rough consensus, document objections and trade-offs, and then record a decision. Urgent security containment may happen privately first and must be documented publicly after disclosure is safe.

## Independence from adopters

No adopter receives a private public-roadmap lane. Requirements originating in a private environment must be generalized before entering the public backlog. Public decisions are based on the reusable capability, project principles, maintenance cost, and community benefit—not on the identity of the requester.

## Releases

Maintainers approve releases after required checks pass, security-sensitive changes are reviewed, provenance is available, and release notes contain no consumer-specific material.

## Changes to governance

Governance changes require a dedicated pull request, an ADR, and a reasonable public review window.
