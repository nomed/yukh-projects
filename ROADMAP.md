# Roadmap

The roadmap is capability-led and intentionally free of adopter commitments. Dates are assigned only when scope, maintainers, and security requirements are understood.

## 0. Foundation

- Establish governance, security, neutrality, contribution, and context contracts.
- Introduce policy checks and immutable action pins.
- Define the canonical architecture and threat model.

## 1. Clean-room migration

- Inventory reusable capabilities without importing legacy history.
- Review every migrated file for provenance, neutrality, secrets, and current relevance.
- Replace environment-derived fixtures with intentionally synthetic datasets.
- Establish deterministic unit, contract, and integration tests.

## 2. Hardened preview

- Deliver plan and dry-run workflows before apply workflows.
- Define least-privilege authentication profiles.
- Add concurrency, retry, rate-limit, rollback, and audit semantics.
- Publish a threat model and operational safety guide.

## 3. Stable release

- Publish versioned schemas and compatibility guarantees.
- Produce signed releases, provenance, checksums, and software bills of materials.
- Document upgrade and recovery procedures.

## 4. Community scale

- Expand neutral examples and extension contracts.
- Formalize maintainer succession and release stewardship.
- Measure project health without collecting adopter identity or private usage data.
