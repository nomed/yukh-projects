# Controlled legacy apply v1 qualification

- Governing issue: [#101](https://github.com/nomed/yukh-projects/issues/101)
- Scope: synthetic implementation evidence only
- Provider access: none
- Live apply: not authorized

## Qualified boundary

The apply Action and CLI accept exact mode `legacy-apply-v1`. This mode selects
the version-1 compatibility planner through a closed internal discriminator;
policy text cannot select or substitute the host. Native mode remains exact
`apply`, and dry-run bundles remain structurally separate from both.

The controlled lifecycle retains distinct credentials, signed exact-plan
approval, protected host capsule, nonce consumption, fenced lease, fresh
preflight, one-shot mutation, targeted invalidation, verification, final zero
convergence, stable diagnostics, and redacted public output.

## Deterministic evidence

Synthetic organization-owned repository fixtures run with GraphQL remaining
zero. The first pass plans and accepts one native Issue Type REST mutation,
invalidates the affected item state, verifies convergence, and ends with zero
remaining operations. A separately constructed second runtime observes a
zero-operation plan and sends no additional mutation.

Negative tests reject unversioned aliases, mode substitution, changed policy,
shared credentials, stale or substituted approval, replay, lease loss, partial
failure, unsupported operation kinds, and disclosure in public diagnostics.
Bundle reproducibility and startup smoke tests remain release gates.

## Authorization boundary

This qualification does not authorize publication, deployment, provider
credentials, consumer workflow changes, live apply, backfill, field removal,
legacy removal, or migration completion. Any real first or second apply requires
its own fresh plan and explicit approval.
